# HTML Accessibility

## این مبحث چیست؟

دسترسی‌پذیری HTML یعنی ساختن محتوای وب به شکلی که همه‌ی کاربران، از جمله افراد دارای محدودیت‌های جسمی یا شناختی، بتوانند از آن استفاده کنند. این موضوع در HTML از ساختار معنایی، برچسب‌ها و ویژگی‌های مناسب آغاز می‌شود.

## چرا از آن استفاده می‌کنیم؟

- افزایش کیفیت تجربه‌ی کاربری
- سازگاری بهتر با صفحه‌خوان‌ها و ابزارهای کمکی
- رعایت استانداردهای حرفه‌ای در پروژه‌ها

## چه زمانی استفاده می‌کنیم؟

- فرم‌های ورود و ثبت سفارش
- منوها و ناوبری
- بخش‌های متنی و دکمه‌های اصلی

## چه زمانی نباید استفاده کنیم؟

- وقتی semantic structure به‌صورت کامل رعایت نشده باشد
- وقتی برچسب‌ها یا عنوان‌ها نامفهوم باشند
- وقتی دسترسی از طریق کلیدبورد یا صفحه‌خوان در نظر گرفته نشده باشد

## تفاوت با عناصر مشابه

- HTML semantic برای معنای ساختار استفاده می‌شود
- ARIA برای افزودن معنی بیشتر به عناصر غیرsemantic است
- `div` و `span` اگر بدون درک درست استفاده شوند، دسترس‌پذیری را کاهش می‌دهند

## بهترین روش‌های استفاده

- عناصر semantic را ترجیح دهید
- برای هر فرم، `label` دقیق داشته باشید
- برای لینک‌ها و دکمه‌ها متن معنی‌دار استفاده کنید
- از `aria-label` و `aria-labelledby` فقط در شرایط ضروری استفاده کنید

## اشتباهات رایج

- نادیده گرفتن `label` برای ورودی‌ها
- استفاده از دکمه‌های غیرمعنی‌دار
- ساختار نامنظم صفحه و منو

## نکات بازار کار

در پروژه‌های واقعی، دسترس‌پذیری به‌عنوان یک مهارت مهم برای code review و UX حرفه‌ای دیده می‌شود. تیم‌های بزرگ معمولاً این موضوع را به‌صورت جدی ارزیابی می‌کنند.

## چک‌لیست یادگیری

- [ ] ساختار semantic را با دسترس‌پذیری هماهنگ می‌کنم
- [ ] برای ورودی‌ها `label` درست می‌گذارم
- [ ] عناصر اصلی را برای صفحه‌خوان‌ها معنی‌دار می‌کنم
- [ ] از ARIA فقط در زمان نیاز استفاده می‌کنم

## تمرین

اکنون یک فایل جدید با نام

HTMLAccessibility.Exercises.html

بساز و تمرین‌های زیر را انجام بده.

1. یک صفحه‌ی فرم ورود با label مناسب و دسترس‌پذیری کامل بساز.
2. یک منوی ناوبری با `aria-label` حرفه‌ای طراحی کن.
3. یک صفحه‌ی داشبورد با دکمه‌ها و بخش‌های قابل تشخیص بساز.
4. یک جدول داده با عنوان‌های معنایی و دسترس‌پذیری مناسب طراحی کن.
5. یک صفحه‌ی خدمات با لینک‌های واضح و section‌های semantic بساز.
6. یک فرم ثبت‌نام با ورودی‌های easy to read طراحی کن.
7. یک صفحه‌ی FAQ با دسترسی قابل قبول برای صفحه‌خوان بساز.
8. یک صفحه‌ی محصول با دکمه‌ها و متن‌های واضح ایجاد کن.
9. یک منوی هوشمند با کلیدبورد و دسترس‌پذیری حرفه‌ای بساز.
10. یک نسخه‌ی کامل از صفحه‌ی فروشگاهی با تمرکز بر accessibility طراحی کن.

## درس بعدی

در درس بعدی با مبانی ARIA و ویژگی‌هایی مثل `role` و `aria-label` آشنا می‌شویم.
