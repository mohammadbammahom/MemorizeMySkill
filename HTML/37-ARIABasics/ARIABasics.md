# ARIA Basics

## این مبحث چیست؟

ARIA مجموعه‌ای از ویژگی‌ها و نقش‌ها برای افزودن معنی به عناصر HTML است، به‌ویژه زمانی که HTML semantic به‌تنهایی کافی نیست. این ابزار برای دسترس‌پذیری بهتر و تعامل‌های پیچیده کاربرد دارد.

## چرا از آن استفاده می‌کنیم؟

- توضیح نقش و وضعیت عناصر برای صفحه‌خوان‌ها
- کنترل بهتر رفتارهای تعاملی سفارشی
- افزایش دسترس‌پذیری برای رابط‌های پیچیده

## چه زمانی استفاده می‌کنیم؟

- وقتی عنصر به شکل semantic طبیعی ساخته نشده است
- برای `role`های خاص مثل navigation، region و toolbar
- برای `aria-expanded`، `aria-hidden` و `aria-label`

## چه زمانی نباید استفاده کنیم؟

- وقتی HTML semantic خودش کافی است
- وقتی ARIA برای چیزی که semantic دارد استفاده می‌شود
- وقتی نقش یا وضعیت عنصر به‌صورت استاندارد در HTML قابل بیان است

## تفاوت با عناصر مشابه

- `role` نقش عنصر را مشخص می‌کند
- `aria-label` متن جایگزین برای دسترس‌پذیری است
- `aria-hidden` برای مخفی کردن محتوای غیرضروری از صفحه‌خوان استفاده می‌شود
- `aria-expanded` برای وضعیت باز یا بسته بودن یک عنصر استفاده می‌شود

## بهترین روش‌های استفاده

- از ARIA فقط به‌عنوان کمک‌کننده استفاده کنید
- ابتدا semantic HTML را درست پیاده‌سازی کنید
- نقش‌ها را دقیق و معنی‌دار تعیین کنید

## اشتباهات رایج

- استفاده‌ی بی‌مورد از ARIA
- تضاد بین HTML semantic و ARIA
- استفاده از `aria-label` به‌جای `label`

## نکات بازار کار

در پروژه‌های حرفه‌ای، استفاده‌ی درست از ARIA مخصوصاً در رابط‌های پیچیده و اپلیکیشن‌های داخلی یکی از نشانه‌های تجربه‌ی کاربری خوب است.

## چک‌لیست یادگیری

- [ ] نقش `role` را می‌فهمم
- [ ] `aria-label` و `aria-hidden` را به‌درستی استفاده می‌کنم
- [ ] `aria-expanded` را برای حالت‌های قابل باز و بسته به‌کار می‌برم
- [ ] ARIA را فقط زمانی استفاده می‌کنم که semantic کافی نیست

## تمرین

اکنون یک فایل جدید با نام

ARIABasics.Exercises.html

بساز و تمرین‌های زیر را انجام بده.

1. یک دکمه‌ی منو با `aria-expanded` بساز.
2. یک region با `role="region"` و `aria-label` طراحی کن.
3. یک بخش پنهان با `aria-hidden` ایجاد کن.
4. یک نوار ابزار با `role="toolbar"` بساز.
5. یک بخش FAQ با `aria-controls` و `aria-expanded` طراحی کن.
6. یک فرم با `aria-label` برای ورودی‌های مهم بساز.
7. یک کارت `button` با نقش‌های مناسب ایجاد کن.
8. یک صفحه‌ی داشبورد با بخش‌های دسترس‌پذیر بساز.
9. یک نمونه‌ی منوی کشویی با state مناسب طراحی کن.
10. یک نسخه‌ی حرفه‌ای از رابط کاربری با ARIA و semantic سازگار بساز.
