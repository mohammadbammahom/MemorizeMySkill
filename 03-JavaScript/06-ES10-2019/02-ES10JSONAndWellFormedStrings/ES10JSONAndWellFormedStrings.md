# JSON و Well-Formed Strings در ES10

---

## این مبحث چیست؟

در ES10، رفتار JSON.stringify() نسبت به کاراکترهای یونیکد بهبود یافت. این موضوع به‌ویژه در مورد کاراکترهای ناقص یا surrogate-non-well-formed اهمیت دارد و باعث می‌شود سریال‌سازی داده‌های خارجی امن‌تر شود.

---

## چرا از آن استفاده می‌کنیم؟

هنگام کار با داده‌های API یا داده‌های خارجی، ممکن است رشته‌ها شامل کاراکترهای یونیکد خاص باشند. این بهبود باعث می‌شود داده‌های سریال‌شده بهتر با استاندارد JSON هماهنگ شوند.

---

## چه زمانی استفاده می‌کنیم؟

- هنگام ساخت payload برای API
- هنگام ذخیره‌سازی داده‌ی متن
- هنگام ارسال داده به سرویس‌های خارجی
- هنگام اعتبارسنجی داده‌های سریال‌شده

---

## چه زمانی نباید استفاده کنیم؟

اگر داده‌ها ساده و بدون کاراکترهای خاص باشند، نیاز به نگرانی خاصی نیست. این موضوع بیشتر در داده‌های پیچیده و خارجی مهم است.

---

## تفاوت با مفاهیم مشابه

| مفهوم | کاربرد |
|---|---|
| JSON.stringify() | تبدیل object به متن JSON |
| JSON.parse() | تبدیل متن JSON به object |
| well-formed JSON | جلوگیری از تولید داده‌های ناسازگار با استاندارد |

---

## مثال‌های واقعی

در برنامه‌های Node.js یا Front-End، داده‌هایی که از API می‌آیند باید به‌صورت امن سریال و Parse شوند.

---

## بهترین روش‌های استفاده

- برای داده‌ی API از JSON.stringify() استفاده کن
- پیش از ارسال داده، آن را validate کن
- اگر داده‌ها از منبع خارجی هستند، به یونیکد توجه کن

---

## اشتباهات رایج

1. تصور این‌که JSON.stringify() همیشه داده‌ی کامل و استاندارد تولید می‌کند
2. فراموش کردن JSON.parse() برای بازسازی داده
3. نادیده گرفتن داده‌های خارجی
