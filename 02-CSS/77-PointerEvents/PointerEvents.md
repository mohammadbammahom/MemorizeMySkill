# CSS Pointer Events
---
## این مبحث چیست؟
ویژگی `pointer-events` مشخص می‌کند که آیا یک عنصر قادر به دریافت کلیک، اشاره‌گر موس یا لمس باشد. با استفاده از این ویژگی می‌توان تعامل با عناصر را کنترل کرد.
---
## چرا از آن استفاده می‌کنیم؟
- برای غیرفعال کردن کلیک روی عناصر غیر فعال.
- برای عبور دادن کلیک‌ها به عناصر پشت‌زمینه.
- برای ایجاد طرح‌هایی که برخی بخش‌ها فعال و بقیه غیرفعال باشند.
- برای مدیریت تعامل در لایه‌های روی هم قرار گرفته.
---
## چه زمانی استفاده می‌کنیم
- وقتی می‌خواهیم روی یک دکمه غیر فعال کلیک نشود:
```css
button.disabled {
  pointer-events: none;
}
```
- وقتی می‌خواهیم کلیک از روی لایه رویی به لایه زیرین عبور کند:
```css
.overlay {
  pointer-events: none;
}
```
- وقتی می‌خواهیم یک عنصر فقط دیدنی باشد اما قابل کلیک نباشد:
```css
.card { pointer-events: none; }
```
---
## چه زمانی نباید استفاده کنیم
- وقتی عنصر باید همچنان تعامل کامل داشته باشد.
```css
.link { pointer-events: auto; }
```
- وقتی باعث سردرگمی کاربر می‌شود.
- وقتی لازم است روی عنصر فوکوس صفحه کلید هم اعمال شود.
---
## تفاوت با ویژگی‌های مشابه
| ویژگی | کاربرد | تفاوت |
|-------|--------|-------|
| `pointer-events` | کنترل تعامل اشاره‌گر | روی کلیک و hover اثر می‌گذارد |
| `visibility` | کنترل دیدن عنصر | عنصر را پنهان یا نمایش می‌دهد |
| `opacity` | شفافیت | فقط ظاهر را تغییر می‌دهد |
---
## بهترین روش‌های استفاده
- برای حالت disable از `pointer-events: none` و ظاهر مناسب استفاده کنید.
- عناصر تعاملی را با `pointer-events: auto` نگه دارید.
- موقع ساخت overlay ها دقت کنید که تنها بخش‌های لازم تعامل‌پذیر باشند.
- در موبایل نیز رفتار لمس را آزمایش کنید.
---
## اشتباهات رایج
- ❌ قرار دادن `pointer-events: none` روی تمام عناصر والد:
```css
.container { pointer-events: none; }
```
- ❌ غیرفعال کردن عناصر بدون ارائه بازخورد بصری.
- ❌ استفاده از این ویژگی برای پنهان کردن محتوا.
---
## نکات بازار کار
- در طراحی لایه‌های تعاملی، `pointer-events` می‌تواند تجربه کاربری را بهبود دهد.
- در مصاحبه باید تفاوت بین `none` و `auto` را توضیح دهید.
- در بازبینی کد بررسی کنید آیا رفتار کلیک و لمس با منطق صفحه همخوانی دارد.

## تمرین
یک کارت با لایه پوششی بسازید که لایه رویی دیده شود اما هنوز زیر آن دکمه قابل کلیک باشد.

مراحل انجام تمرین:

1. در HTML یک کارت (`div`) بسازید که شامل این بخش‌ها باشد:
   - یک تصویر یا بلوک رنگی به عنوان پس‌زمینه.
   - یک لایه پوششی (`div`) در بالای کارت.
   - یک دکمه (`button`) یا لینک در داخل کارت.

2. در CSS کارت را به `position: relative;` تنظیم کنید.

3. برای لایه پوششی این قوانین را بنویسید:
   - `position: absolute;` و تنظیمات `top`, `left`, `right`, `bottom` تا تمام کارت را بپوشاند.
   - `background-color: rgba(0, 0, 0, 0.35);` یا رنگ مشابه.
   - `pointer-events: none;` تا کلیک به عناصر زیر منتقل شود.

4. برای دکمه، استایل قابل مشاهده و قابل کلیک تعریف کنید:
   - `background-color`, `padding`, `border-radius` مناسب.
   - در صورت hover، تغییر رنگ یا سایه ملایم داشته باشد.

5. بررسی کنید که با وجود لایه پوششی، دکمه هنوز کلیک می‌شود و ظاهر کارت حرفه‌ای است.

نتیجه نهایی:
یک کارت طراحی کنید که لایه پوششی نیمه‌شفاف دارد، اما به‌خوبی کلیک‌ها به دکمه زیر پوشش منتقل می‌شوند و تجربه کاربری مناسبی ایجاد می‌کند.
